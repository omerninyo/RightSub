# 💎 מפרט ארכיטקטוני: מנוע ליטוש סמנטי, הגהה ובקרת איכות מבוסס AI (`rightsub polish`)

<p align="right">
  <b>שפה / Language:</b>
  <b>עברית</b> |
  <a href="FEATURE_AI_POLISH_AND_QC.md"><b>English</b></a>
</p>

מסמך זה מגדיר את הארכיטקטורה, חוזה הנתונים, ממשק הפקודה וזרימת העבודה של רכיב הליטוש הסמנטי ובקרת האיכות מבוסס ה-AI של **RightSub**: פקודת `rightsub polish` (או `rightsub qc-ai`).

מטרת הרכיב היא לאפשר השבחה והגהה של כתוביות עבריות קיימות (כתוביות ישנות, תרגומים אנושיים לא מלוטשים, או תרגומי מכונה בוסריים — דוגמת גרסת הקהילה של *Star Wars 4K77*) **מבלי לתרגם את הסרט מאפס**, תוך תיקון שיבושי קאנון, שגיאות מגדר, וביטויים מילוליים.

---

## 1. הבעיה והמוטיבציה ההנדסית

ברשת קיימים עשרות אלפי קובצי כתוביות בעברית לסרטים קלאסיים וסדרות. ברובם המוחלט (כ-85%–90%), תזמון הדיאלוגים מדויק והעברית הבסיסית תקינה, אך הם סובלים מ-3 פגמים סמנטיים מהותיים:
1. **שיבושי קאנון ומונחים היסטוריים (Canon Drift):** שמות דמויות, מקומות וכלי נשק שתורגמו בצורה לא עקבית (למשל: *"חרב לייזר"* במקום *"חרב אור"*, או *"מוף"* במקום *"גרנד מוף"*).
2. **היפוכי מגדר בפניות ישירות (Gender Flipping):** תרגום המילה `You` כזכר בפנייה לדמות נשית (למשל פנייה לליאה בלשון זכר).
3. **תחביר אנכרוניסטי או תרגום מילולי של סלנג (Idiom Mistranslations):** תרגום מילולי של ביטויים אנגליים שמאבדים את משמעותם המקורית.

תרגום הסרט מאפס באמצעות מודל שפה מבזבז טוקנים רבים, מסתכן באובדן ניסוחים אנושיים איכותיים קיימים, ועלול לשבור תזמונים. **מנוע הליטוש פועל לפי עקרון מרחק עריכה מינימלי (Minimal Edit Distance)**.

## 2. השוואת פקודות RightSub לעבודה עם כתוביות קיימות

| פקודה | מטרת שימוש | מגע בטקסט עצמו | שימוש ב-AI | צריכת טוקנים |
| :--- | :--- | :---: | :---: | :---: |
| `rightsub fix-plex` | תיקון טכני של כיווניות פיסוק (RLM), קידוד ופרסומות. | ❌ ללא שינוי תוכן | ❌ לא | 0 |
| `rightsub qa` | בדיקה דטרמיניסטית של מבנה, תזמונים, ג'יבריש ומגדר בסיסי. | ❌ דוח בלבד | ❌ לא | 0 |
| `rightsub auto` | הפעלה אוטונומית (מחלץ, מתקן פלקס או מכין תרגום מאפס). | ✔️ מלא (אם מתרגם) | ✔️ כן (אם נדרש) | 100% |
| **`rightsub polish`** | **הגהה לשונית, תיקון מגדר סמנטי ויישור קאנון על תרגום קיים.** | **✔️ תיקונים סלקטיביים בלבד** | **✔️ כן (בקרת איכות)** | **~15%–20%** |

---

## 3. ממשק שורת הפקודה (CLI Interface)

```bash
# בדיקה וליטוש של כתובית עברית מול מקור אנגלי:
rightsub polish "Star Wars (1977).he.srt" --en "Star Wars (1977).en.srt"

# שימוש במזהה TMDb ייעודי למשיכת קאנון ושיוך דמויות:
rightsub polish "Gladiator.he.srt" --en "Gladiator.en.srt" --tmdb-id 98

# הפעלה במודל מקומי חינמי ואופליין דרך Ollama:
rightsub polish "Movie.he.srt" --en "Movie.en.srt" --ollama --model qwen2.5:7b

# הפקת דוח שינויים בלבד ללא דריסת הקובץ (Dry Run / Audit Mode):
rightsub polish "Movie.he.srt" --en "Movie.en.srt" --diff-only
```

## 4. ארכיטקטורת הפייפליין של מנוע הליטוש

```text
[Movie.en.srt] ──┐
                 ├──> [1. צימוד בלוקים דו-לשוני] ──> [2. הזרקת קאנון ומגדר מ-TMDb]
[Movie.he.srt] ──┘                                                    │
                                                                      ▼
[קובץ סופי מתוקן: Movie.he.polished.srt] <── [4. יישום והזרקת RLM] <── [3. פרומפט ביקורת וליטוש AI]
                 │
                 └──> [5. דוח שינויים מפורט: Movie_polish_diff.md]
```

### שלב 1: צימוד בלוקים דו-לשוני (Bilingual Alignment)
קריאת שני קובצי ה-SRT וצימוד כל שורה אנגלית לשורה העברית המקבילה לה לפי חותמת זמן ומספר סידורי:
```json
{
  "index": 142,
  "timing": "00:18:22,100 --> 00:18:24,800",
  "en": "Your father's lightsaber. This is the weapon of a Jedi Knight.",
  "current_he": "חרב הלייזר של אביך. זה הנשק של אביר ג'דיי."
}
```

### שלב 2: הזרקת מידע ישויות וקאנון מ-TMDb
חילוץ שמות השחקנים, הדמויות והמגדר הדקדוקי מתוך ה-API של TMDb, לצד הזרקת מילון מונחי זיכיון (למשל: סדרת Star Wars, שר הטבעות, הארי פוטר, מארוול).

### שלב 3: חוזה הפרומפט המבוקר (Constrained Polish Prompt)
הפרומפט מנחה את מודל השפה לפעול כעורך לשוני מחמיר:
1. **כלל השימור (Conservation Rule):** אם השורה העברית מדויקת ונשמעת טבעית — **אין לשנותה**.
2. **תיקון קאנון:** איתור מונחים שגויים והחלפתם במונח הקאנוני המוכר.
3. **תיקון מגדר:** התאמת פניות לפי הדובר והנמען בסצנה.
4. **ריענון תחביר עילג:** פירוק משפטים מתורגמים מילולית והמרתם לעברית קולנועית שוטפת.
5. **מגבלות כתוביות:** מקסימום 38–40 תווים לשורה, מקסימום 2 שורות לבלוק.

### שלב 4: מבנה הפלט של ה-AI
המודל מחזיר אך ורק אובייקט JSON המכיל את השורות ששונו בפועל:
```json
{
  "cues": [
    {
      "index": 142,
      "original_he": "חרב הלייזר של אביך. זה הנשק של אביר ג'דיי.",
      "polished_he": "חרב האור של אביך. זהו נשקו של אביר ג'דיי.",
      "reason": "מינוח קאנוני (Lightsaber = חרב אור) + שיפור תחביר"
    }
  ]
}
```

### שלב 5: הפקת דוח שינויים (Diff Audit Report)
לצד עדכון קובץ הכתוביות, המערכת מייצרת דוח Markdown ברור המאפשר סקירה מהירה:

## 5. בטיחות ושמירה על קובצי מקור (Non-Destructive by Default)

בהתאם לכללי הליבה של RightSub:
- קובץ המקור `Movie.he.srt` מגובה אוטומטית כ-`Movie.he.original.srt` לפני כל שינוי.
- הקובץ המשופר נשמר תמיד עם תווי RLM סמויים וקידוד UTF-8 מלא לתאימות 100% עם נגני Plex, Infuse ו-Apple TV.
